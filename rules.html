Operating Model - Rules & Ownership

Detailed rules for each step of the operating model

E2E including backend/frontend
E2E software functional requirements optimal definition Owner: Project Leader
  • Requirements must be created and modified through TARS.
  • The Project Leader must submit a requirement or a new version of a requirement. Until submitted, the requirement can be freely modified without creating a new version — but the developer will not consider it. The developer only considers submitted versions.
  • The Project Leader is responsible for creating a reasonably optimal functional requirement. If the user asks for unreasonable or useless features, the Project Leader must challenge them and propose a better solution.
  • The Software Engineer is responsible for providing feedback if alternative approaches could lead to a significantly better technical implementation.
  • In case of disagreement, the Project Leader has final ownership of the functional requirement, but should consider escalating the decision if needed.
Functional testbook & acceptance criteria creation Owner: Project Leader
  • A first version of the functional testbook and acceptance criteria must be shared together with the functional requirements.
  • Each test case must include the full user journey to be verified, along with its acceptance criteria, in order to allow automatic scraping with AI.
  • The Project Leader is responsible for creating a significant testbook with clear acceptance criteria, such that if 100% of test cases are passed and all acceptance criteria are met, UAT will raise only marginal bugs.
  • The Software Engineer is responsible to: generate the Playwright code to execute all test cases against their acceptance criteria, execute them, and deliver software that passes 100% of test cases and meets all acceptance criteria.
  • The Software Engineer is responsible for verifying that the software has no evident objective bugs, even if not explicitly specified in the requirements, test cases or acceptance criteria.
Frontend/backend ark design Owner: Software Engineer
  • The Software Engineer is the sole responsible for this activity and must ensure compliance with both the AI Factory guidelines and the functional requirements.

Automation
Automation requirement definition Owner: Project Leader
  • The Project Leader is responsible for defining exactly:
    • The expected input and output of the automation
    • The expected volumes to be managed
    • The expected SLAs
    • Any cost constraints
    • The metrics to be maximized and the constraints to be respected
  • Submission of automation requirements through TARS to be evaluated
Train/test dataset request definition Owner: AI Developer
  • The AI Developer is responsible for defining the exact minimum requirements of the dataset in terms of size and distribution.
  • If it's not possible to satisfy the minimum requirements, the AI Developer and the Project Leader can agree on a different proposal. The AI Developer remains responsible for delivering an experiment that is statistically significant and will mirror the production results.
  • If the AI Developer is not confident about the relevance of the dataset, he/she is responsible to escalate the topic in order to discuss and agree a GO / No-GO.

Automation flow (agent / algorithm / LLM call flow) technical design Owner: AI Developer
  • The AI Developer is responsible for designing the flow / algorithm that satisfies all requirements (ref. rule 1 of Automation requirement definition).
  • The flow must be designed to follow the basic cloud production environment requirements (e.g. stateless).
  • The AI Developer can involve the Software Engineer only when the flow design is almost final.
  • The Software Engineer is responsible for reviewing the flow and confirming or proposing the key technical and infrastructure choices and constraints.
  • If a technical / infrastructure choice impacts the AI flow (to maximize software stability / maintainability), the AI Developer and the Software Engineer should agree on it. In case of disagreement, the topic must be escalated — as the AI Developer is the end responsible for automation performance and the Software Engineer is the end responsible for end-to-end production software performance.
  • After the review, the AI Developer cannot change the flow anymore.
